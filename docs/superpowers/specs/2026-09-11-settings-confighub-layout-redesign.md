# ConfigHub（工作区设置）现代化分栏布局重构设计规格

- **日期**：2026-09-11
- **状态**：已评审通过 (Approved)
- **目标组件**：`web/frontend/src/components/ConfigHub.tsx` 及相关子组件/测试用例

---

## 1. 背景与现状问题

当前 `/settings/workspace`（ConfigHub）页面与 CodeAgent 的其他核心页面（如 `McpPage`、`ResourceHub`、`InstancesPage`、`LaunchPad`）存在明显的视觉体验和交互断层：
1. **单一长列堆叠**：4 个大模块（通用偏好、工作区注册表、资源分组、网络代理）纵向平铺在单一容器内，页面纵深极大，用户需要不断往下滚动才能找到目标配置；
2. **容器与视口不协调**：其他页面采用全高弹性布局（`h-full flex`），而 ConfigHub 采用了限制宽度的居中模式（`max-w-5xl mx-auto`）和巨大的底内边距（`pb-28`）；
3. **悬浮吸底保存条**：保存/放弃按钮位于页面最底部的悬浮条中，当用户在页面上半部分编辑时，缺少明确的视觉锚点；
4. **工作区录入体验生硬**：工作区项直接使用裸露的 input 框展示在列表中，添加新工作区在最下方追加一排空白 input，破坏了卡片化与现代 IDE 的精致质感。

---

## 2. 设计目标

1. **视觉语言统一**：完全对齐 `McpPage` 和 `ResourceHub` 的设计语言——采用 **「左侧设置分类导航 + 右侧独立内容工作区」** 的双栏全高弹性架构；
2. **零长滚屏困扰**：分类独立查看与编辑，主内容区内部独立滚动；
3. **保存状态明确常驻**：Save / Discard 按钮常驻于顶栏或导航底栏，无需翻页寻找；
4. **卡片化与弹窗操作**：工作区以项目卡片（项目名、路径、分组徽章、健康状态、快速打开终端）展示，添加工作区支持标准 Modal 对话框录入，并支持搜索过滤。

---

## 3. 架构与组件设计

### 3.1 布局分区

- **根容器**：`flex h-full min-h-0 flex-col md:flex-row gap-4`
- **左侧导航栏 (`ConfigNavRail`)**：
  - 固定宽度：`w-full md:w-56 shrink-0`
  - 分类项：
    1. **工作区目录 (`workspaces`)**：
       - 图标：`Folder`
       - 角标：当前项目总数（如 `3`）；若有失效路径，显示黄色警告角标。
    2. **资源分组 (`groups`)**：
       - 图标：`Layers`
       - 角标：当前分组数量（如 `3`）。
    3. **常规偏好 (`general`)**：
       - 图标：`Languages` / `Settings`
    4. **网络代理 (`proxy`)**：
       - 图标：`Globe`
       - 角标：配置的代理网关数量。
  - 导航状态保持：采用 `ACTIVE_CHIP`（与同级页面一致），点击无缝切换右侧面板。
  - 底部快速保存卡片：当存在未保存更改（`dirty`）时，左下角/右上角清晰展示未保存提示、放弃修改与保存全部按钮。

### 3.2 右侧主内容区 (`ConfigWorkspaceArea`)

- **外层容器**：`flex-1 min-w-0 flex flex-col h-full overflow-hidden glass-card p-5 md:p-6`
- **统一头部 (Header)**：
  - 左侧：当前分类标题（Title）与一句话描述（Subtitle）；
  - 右侧：对应分类的快捷操作按钮（如 `+ 添加工作区`、`+ 新建分组`、`+ 添加网关`）及保存动作。

#### 3.2.1 分类详情：工作区目录 (Workspaces)
- **顶部操作栏**：
  - 搜索框（`SearchInput`）：按项目名或路径模糊过滤；
  - 一键清理失效路径按钮：若检测到不存在的物理路径，提示 `清理 X 个失效路径`；
  - `+ 添加工作区` 按钮：点击唤起 `AddWorkspaceModal`。
- **列表/卡片流**：
  - 每个工作区渲染为精致的项目卡片：
    - 项目名提取（如 `/home/cy/github/my-app` -> **my-app**，加粗突出）；
    - 路径字体：Mono 字体，截断自适应；
    - 状态灯：`CheckCircle2`（绿色，有效）或 `AlertTriangle`（黄色，路径不存在）；
    - 归属分组：Badge 标签下拉选择（快速调整所属分组）；
    - 快捷按钮：
      - `[打开终端]`：直接跳转到 `/agent/terminal` 并挂载该工作区；
      - `[删除]`：从注册表中移除。

#### 3.2.2 分类详情：资源分组 (Groups)
- **操作栏**：`+ 新建分组`（内联或弹窗录入）；
- **卡片展示**：
  - 分组名称大写标识；
  - 资源统计 Badge（Skills/Prompts/Hooks/Plugins 各自包含数量）；
  - `查看并配置资源` 按钮：点击带参数跳转至 `/settings/resources?group=<name>`；
  - 删除分组按钮（保护默认系统分组如 `codeagent`, `common` 不可删除）。

#### 3.2.3 分类详情：常规偏好 (General)
- **本地生效说明**：提示配置生效于本地 CLI 与 Web 端；
- **界面语言选择器**：双语 Radio 按钮卡片，即时点击保存并同步至系统；
- **私有资源根路径**：输入 `$CODEAGENT` 自定义路径，附带路径占位提示与规范输入框。

#### 3.2.4 分类详情：网络代理 (Proxy)
- **网关列表**：
  - 主机与端口卡片列表；
  - 支持快捷添加、编辑与删除代理网关；
  - 支持测试代理连通性或格式校验。

---

## 4. 状态与数据管理

1. **延续既有数据流与安全机制**：
   - 保持原有的 `useProject()`、`config`、`projects`、`groups` 上下文；
   - 维持 `savedSnapshot` 与 `draftSnapshot` 差异比对（`dirty` 计算）；
   - 保留防并发刷新的 `isDirty` 保护逻辑；
   - 语言配置（`language`）依然保持即选即持久化生效的既有设计。
2. **弹窗状态**：
   - `AddWorkspaceModal`：录入项目绝对路径（带校验）并选择初始分组；
   - 支持回车提交与 ESC 关闭。

1. **单元测试 (`ConfigHub.test.tsx`)**：
   - 验证分类切换（工作区、分组、常规、代理）能够正确渲染对应视图；
   - 验证添加工作区 Modal 的打开、录入与提交；
   - 验证移除工作区与清理失效路径；
   - 验证多语言切换；
   - 验证脏检查与保存/放弃交互；
2. **系统回归测试**：
   - 运行 `bun run test` 确保全部前端单测通过；
   - 运行 `bun run build` 确保前端构建打包 0 错误；
   - 运行 `uv run ruff check .` 与 `uv run pytest` 确保后端全绿。
