# 自动化工作台（Automations Studio）UI/UX 全面重构设计规范

- **日期**: 2026-09-08
- **状态**: Draft (待用户确认)
- **目标模块**: `web/frontend/src/components/TaskDashboard/`, `web/frontend/src/components/LogViewer.tsx`, `web/frontend/src/components/CronPage.tsx`

---

## 1. 背景与现状问题

用户在实际使用中反馈自动化模块（特别是任务详情页）“特别抽象，很不好用”。经截图与代码走查，定位到以下核心交互痛点：

1. **视口与空间严重浪费**：
   - 页面写死 `max-w-4xl mx-auto`，在现代高分辨率及宽屏显示器上左右两侧留白超过 50%，内容被拘束在狭窄的中部。
2. **顶部控制栏拥挤与截断**：
   - 工作区路径下拉框写死 `max-w-56`，稍长路径直接被截断成 `/home/cy/github/chuanyue!`，无法判断当前工作目录；
   - 返回、编辑、删除、工作区、引擎、运行/重试所有按钮单排平铺堆砌，缺乏操作层级。
3. **任务内容展示极其原始（抽象核心）**：
   - 四段式任务定义（目标 Objective、背景 Context、指令 Instructions、验证 Verification）被直接以原始 Markdown 字符串灌入 `<pre>` 标签裸渲染，缺乏格式排版与层级结构；
   - 当任务存在执行记录或有运行日志（`logTaskId`）时，任务内容直接被替换隐藏，导致用户在查看终端或检查结果时完全无法对照任务指令。
4. **右侧“挂载技能”占比过大且信息低效**：
   - 几个技能卡片占满整列空间，每张卡片仅包含一两行描述，信息密度过低。
5. **各子视图缺乏联动**：
   - 任务定义、实时日志、文件变更、历史运行以及定时计划之间相互割裂，缺乏连贯的工作流体验。

---

## 2. 设计目标与原则

1. **Studio 工作台布局**：去除死板的 `max-w-4xl` 限制，采用全宽自适应容器，左侧主力工作区与右侧轻量检查器配合。
2. **语义化与富文本呈现**：任务蓝图支持多段结构化折叠/展开与真正的 Markdown 富文本渲染（语法高亮、复制块）。
3. **内容与执行常驻双全**：采用顶级选项卡（蓝图 Blueprint、实时终端 Logs、代码变更 Changes、历史运行 History），用户可随时自由切换，执行中不再丢弃任务定义上下文。
4. **高信息密度与精细化控件**：工作区选择器提供友好缩写与完整悬浮提示，操作按钮按危险度与频率进行逻辑分组。
5. **全流程闭环**：任务详情可一键转为定时任务；日志查看器增强搜索、全屏与复制能力。

## 3. 详细设计与界面架构

### 3.1 任务详情页（TaskDetail）重构

#### 3.1.1 顶栏（Studio Header）
* **左侧区**：
  * 面包屑导航：`自动化 / 任务 / <TaskTitle>`，带返回按钮；
  * 任务主标题、描述与状态指示徽标（运行中附带呼吸灯，已完成附带绿色徽标）。
* **右侧操作区（逻辑分组）**：
  * **环境选择组**：
    * 工作区下拉框（自适应宽度，文本显示 `[项目组] 目录名`，title 提供绝对全路径）；
    * 引擎切换下拉框（带有引擎图标，如 Claude、OpenCode、Codex 等）；
  * **主动作组**：
    * 突出显示的「立即运行（Run）」或「停止执行（Stop Execution）」按钮；
  * **辅助动作组**：
    * 「编辑蓝图」次级按钮；
    * 「快捷加入定时任务」按钮（预填至 `/automations/schedules`）；
    * 「删除」危险动作按钮（带二次确认）。

#### 3.1.2 主工作区（左侧 70% 宽）
采用选项卡式容器（持久保持状态）：
1. **「任务蓝图」（Blueprint）Tab**：
   * 自动解析并结构化呈现四段式蓝图：
     * **目标（Objective）**：目标摘要卡片，带主色图标强调；
     * **背景（Context）**：柔和背景容器，说明执行前置上下文；
     * **执行指令（Instructions）**：富文本渲染的编号步骤清单与代码块；
     * **验证标准（Verification）**：明确的验收条件检查清单。
   * 如果任务是阶段式流程（`hasStages`），顶部展示阶段进度条及各阶段状态卡片。
   * 如果任务是自由 Markdown，则通过 `MarkdownMessage` 完整渲染标题、表格、引用与代码高亮。
2. **「执行终端」（Terminal Logs）Tab**：
   * 嵌入 `LogViewer` 终端流；
   * 当任务正在执行或选定了历史记录时，在此处实时刷屏；
   * 提供终端全屏切换、自动滚动开关、一键清空与复制。
3. **「代码变更」（Changes）Tab**：
   * 展示本次或当前选定运行的 Git diff 与文件变更列表。
4. **「历史运行」（Run History）Tab**：
   * 历史运行表格/卡片：引擎、开始时间、耗时、退出码、终态徽章；
   * 点击任意一条历史记录，可直接在该页面切换查看该次运行的日志与代码变更，支持一键“以此参数重新执行”。

#### 3.1.3 侧边检查器（右侧 30% 宽）
1. **当前/最近运行指标卡**：
   * 引擎标识卡；
   * 执行耗时与退出码；
   * 状态指示标签（Running / Completed / Failed / Stopped）。
2. **挂载的技能与上下文（Skills & Prompts）**：
   * 紧凑型列表展示技能名称、简要描述及关联脚本数量标签；
   * 点击可在弹出模态框或展开面板中查看技能具体源码。
3. **快捷定时卡片**：
   * 如果该任务已配置定时计划，展示下次触发时间；未配置则展示“一键创建定时计划”。

---

### 3.2 任务列表（TaskList）与模板画廊体验增强

1. **响应式宽屏网格**：解除 `max-w-4xl`，支持 `grid-cols-1 md:grid-cols-2 xl:grid-cols-3` 响应式网格布局。
2. **卡片视觉优化**：
   * 区分阶段任务与普通蓝图卡片；
   * 卡片展示上次运行状态（成功/失败点）、耗时、关联工作区和引擎标签；
   * 搜索与新建任务按钮位置更加平衡。

---

### 3.3 日志查看器（LogViewer）增强

1. **日志文本检索**：增加简易搜索栏，快速定位包含特定关键词（如 `Error`, `Failed`, `commit`）的行。
2. **控制工具条**：
   * 「自动滚到底部」开关（避免用户翻看上方报错时被新输出强制打断）；
   * 「复制全部日志」按钮；
   * 「放大全屏查看」模式。

---

### 3.4 技术约束与实现考量

1. **依赖约束**：严禁引入新的外部 npm 依赖，使用现有 `react-markdown`、`lucide-react` 及 Tailwind CSS。
2. **后端契约兼容**：不修改既有 API 协议字段，所有数据结构完全复用既有的 `Task`, `RunStatus`, `ScheduleRecord`。
3. **多语言严格对齐**：所有新增或改动文案必须在 `en.ts` 与 `zh.ts` 同步维护。
4. **测试保护**：`web/frontend/src/__tests__/` 下的所有现有单测（包括 `TaskDashboard.test.tsx`, `TaskList.test.tsx`, `App.test.tsx`, `CronPage.test.tsx`）必须持续全绿，并追加相关测试用例。
